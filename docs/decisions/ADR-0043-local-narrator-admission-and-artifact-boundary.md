# ADR-0043: Gate local narration behind reviewed artifacts and runtime capabilities

- Status: Accepted for M7.11 architecture; optional runtime/model activation deferred
- Date: 2026-11-16

## Context

M7.11 explicitly permits architecture with model downloads conditional on
schedule/performance. There is no accepted narrator artifact/runtime with Traelyx
quality, memory, cancellation, latency and battery evidence. Upstream mobile
support establishes feasibility, not acceptance. Adding a neural runtime now
would create an unmeasured APK, memory and lifecycle obligation.

## Decision

Share the pure M7.10 reviewed-wording input/output validator between providers.
Local runtimes receive categorical wording input and a verified artifact path,
with no credential or cloud fallback. Only indices selecting existing lines may
change; timings, scores, detections and safety state are outside this contract.

Use a strict, bundled catalog (currently empty), exact versioned manifests,
runtime/format/version/API/ABI/offline/cancellation admission, explicit size and
license consent, app-private no-backup storage and streaming SHA-256 verification.
The installed app's signature authenticates the bundled manifest/digest. Remote
manifests, custom URLs, runtime executable downloads and unpinned weights are not
accepted. A future transport needs a separate endpoint/distribution review.

Stage and verify before atomic publication. Reverify before each runtime use and
hold an exclusive lease through runtime cleanup. Cancellation closes the
read-only hash worker file and waits for its exit. Isolate termination alone
does not establish native file-handle cleanup. Keep corrupt artifacts until explicit
removal; recognize incomplete staging after restart. Removal refuses links or
unowned contents and never recursively deletes app data. Report actual managed
bytes, including receipts and partials, without hashing on a settings refresh.

The production source/runtime adapters remain unavailable. Tests and isolated
Pixel QA use small generated bytes and a fake selector; these prove boundaries,
not neural quality or performance. Future adoption must supply pinned artifact
provenance/licenses and physical-device acceptance before changing the catalog.

## Dependency review

Promote existing locked `crypto` **3.0.7** to an exact direct dependency solely for
streaming SHA-256. Its locally inspected license is Dart-project BSD-3-Clause;
it is Dart SDK ecosystem code already in the resolved graph. No resolved version,
transitive package, native library, Android minimum SDK, permission, network
behavior or mandatory cost changes. No runtime/model SDK is added. Security is
bounded by exact bytes/digest from the release-reviewed catalog, rather than a
new cryptographic implementation. Replacement sits inside the artifact verifier.
No claim is made that a dependency audit guarantees absence of vulnerabilities.

## Consequences

Built-in narration remains active. Real neural inference, public model download
distribution, tokenizer/runtime binding, physical memory/latency/battery and
model wording-quality acceptance remain unimplemented gates. No recorder,
Guardian, scoring, database migration or detector promotion occurs. See
[the local-provider contract](../reference/LOCAL_COMMENTARY_V1.md) for bounds,
failure behavior and adoption requirements.
