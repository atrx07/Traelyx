# OPEN_SOURCE_POLICY.md — Licensing & Community Direction

## When to read

Read before first public repository release, importing external code/assets/models, or choosing a license.

## 1. Intent

Traelyx is intended to remain open source during the current project phase and distributed through GitHub Releases.

## 2. License selection

A final repository license has **not** been chosen by this governance pack. The maintainer should deliberately choose one before public launch.

Candidate permissive licenses such as Apache-2.0 or MIT may fit the project's goals, but patent clauses, dependency licenses, model licenses, branding, and contribution expectations should be reviewed before deciding.

Do not let an agent silently select/change the project's license.

## 3. External code

- preserve notices/attribution;
- never copy incompatible/proprietary code;
- record substantial reused components;
- do not assume GitHub visibility means code is licensed for reuse.

## 4. ML models/datasets

Model/data licenses can differ from app code license. Track separately in manifests/registry.

## 5. Branding

Open-source code does not automatically grant rights to future project trademarks/logo if the maintainer later adopts a separate trademark policy. Decide explicitly before major adoption.
