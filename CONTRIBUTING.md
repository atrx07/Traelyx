# Contributing to Traelyx

## Project values

Contributions to Traelyx should preserve originality, local-first operation, privacy, explainability, zero-cost core operation, and safety-conscious competition.

## Before opening code changes

- Read root `AGENTS.md`.
- Read only the relevant subsystem specifications.
- Search for an existing issue/exec plan/ADR before introducing a duplicate concept.
- For broad changes, propose the design before landing a large implementation.

## Pull requests should include

- concise problem statement;
- implementation summary;
- tests performed;
- real-device status if native tracking changed;
- privacy/data-flow impact;
- schema/migration impact;
- screenshots/video for meaningful UI animation changes where practical;
- performance/battery notes for recorder/ML changes;
- documentation updates.

## Originality

Do not submit copied competitor UI, proprietary assets, reverse-engineered scoring logic, or text copied from commercial products.

## Safety

Do not add features that reward dangerous speed, public-road racing, evasion, or risk escalation. High-risk telemetry can be measured and analyzed without becoming a competitive objective.

## AI-assisted contributions

AI-assisted code is allowed. The contributor remains responsible for correctness, licenses, tests, security, and understanding what is being merged.
